## 一、起点：要做什么

需求一句话：**做一个网站，针对性地嗅探智谱（bigmodel.cn）可能存在或即将发布的新模型**。两个硬性功能：

1. 允许用户输入并保存自己的 API Key；
2. 把候选模型名发给智谱 API，通过报错差异判断“该名称是否已存在但暂未对用户开放”——存在而无权访问，往往就是即将发布或正在内测的信号。

核心洞察：模型不存在与模型存在但无权访问，在 API 层的报错是不同的。把错误码/HTTP 状态分类清楚，“猜名字 + 看报错”就构成一台简陋但有效的发布雷达。

## 二、建站与上线

### 2.1 技术形态：纯静态、浏览器直连

- 智谱 API **完整支持 CORS**（对任意 `Origin` 回显放行头），纯静态页面即可由浏览器直连 `https://open.bigmodel.cn/api/paas/v4/chat/completions`，无需后端。
- Key 只存浏览器 `localStorage`（按源隔离、页面掩码），不出本机。官方 `/models` 列表作「已开放」对照（按 Key 保存、新名提示）；每轮扫描用随机乱名重新校准 `1211` 基线，可选付费模型计费对照。
- 后来一轮加固把分类逻辑抽到 `public/probe-logic.js` 并配了 `tests/probe-logic.test.cjs` 单测；引擎加了同条件响应变化对比、空消息对照、六分类统计。

### 2.2 部署：GitHub Pages（gh-pages 分支模式）

- 仓库：`lugoudu/zhipu-model-sniffer`（public），双分支——`main` 源码，`gh-pages` 把 `public/` 平铺到站点根。
- 线上：**https://lugoudu.github.io/zhipu-model-sniffer/**
- 本机 `gh` token 无 `workflow` scope，不能推 `.github/workflows/*.yml`，workflow 样本放 `docs/deploy.yml.sample`，发布走 gh-pages 分支。
- 坑：Pages CDN 缓存约 10 分钟，可用 `gh api repos/lugoudu/zhipu-model-sniffer/pages/builds -X POST` 强制重建；`git push | tail` 会误判管道退出码。

### 2.3 免 Key 旁路通道

1. **HuggingFace zai-org 新仓库扫描**——HF API 对页面 Origin 开放 CORS，浏览器直读最近 50 仓，近 30 天新增高亮并提示「仓库名 → 可试 API 名」。
2. **docs.bigmodel.cn 文档页探测脚本导出**——文档页 404/200 是免 Key 存在性信号；浏览器直连被 CORS 拦，一键导出本机 curl 脚本逐候选探测 text / vlm 两类页面。

## 三、信号学基础：错误码字典

| 信号 | 含义 | HTTP |
| --- | --- | --- |
| code 1000 / 1001 | 认证失败（凡 401 一律视为 Key 无效） | 401 |
| code 1211 “模型不存在” | 该名称不存在 | 400 |
| code 1220 “您无权访问” | **存在，但 ACL 锁住**（白名单/内测） | 403 |
| code 1113 “余额不足或无可用资源包” | 计费关没过 | 429 |
| code 1214 “输入不能为空” | 参数校验——**在模型解析之后**，本身就是“存在”的证据 | 400 |
| JSON 解析 400 | 比一切都早，不含信息 | 400 |

paas 路由门禁管线：

```
JSON 解析 → 模型解析(1211) → 输入校验(1214) → 计费(1113，仅绑定计费的条目) → ACL(1220) → 更深层参数校验 → 200
```

anthropic 路由（`api.z.ai/api/anthropic/v1/messages`）顺序不同：思考参数检查在 ACL 之前，且带计费预检。

## 四、9-23 晚实验全程（重点）

### 背景

26 个字母扫过：`glm-x-preview-{a, f, g, k}` 存在，其余 22 个不存在。用户掌握地面真相——**这批是仅面向获邀测试者的内测模型**。此前四个代号在嗅探站里表现一致：全部 1220。故事从用户注意到一个**不一致**开始。

### 第 1 幕 · 用户的发现①：k 的报错状态突变

**观察（用户）**：重跑嗅探站，`glm-x-preview-k` 的报错与 `glm-x-preview-a/f/g` 不一样了——其余三个仍 1220，k 变成 429/1113 余额类。且用户点出时间维度：**k 之前和那三个一样，现在不一样了**。对纯客户端嗅探器而言，服务端条目状态随时间迁移，正是它存在的意义。

### 第 2 幕 · 用户的发现②：ZCode 接入对照，泄露下一代思考档位

用户在 ZCode 里把四个模型名都接了一遍：

| 模型 | ZCode（anthropic 路由）里的报错 |
| --- | --- |
| glm-x-preview-f / g / a | 无权限访问 |
| **glm-x-preview-k** | **“该模型强制开启思考，需选择 low、high、max”** |

三个后缀死在 ACL，唯独 k 报的是**参数层的错**——不仅证明 k 后端活着且带强制思考硬约束，还提前泄露了**下一代 GLM 的思考档位体系：low / high / max**。用户调好思考档位、配齐余额后，k 回落为 1220，与其他三个一致。

### 第 3 幕 · 用户的发现③：充值对照实验，锁定“余额条件化”

用户怀疑 **k 可能只是唯一一个检查账户余额的**，并亲手做了对照：

- 账户没钱时：k → 1113（与其他三个不同）；
- 充值后：嗅探站里 k → 1220，**重新与其他三个一致**。

并补了交叉验证：**ZCode 接入需要配思考档位，嗅探站从不填思考档位，两者的 k 却都能在充值后归位 1220**——计费关的触发与思考参数无关，两条路由殊途同归，与两条管线里检查顺序的差异对得上。

**结论**：k 的“异常”是**余额条件的函数**——计费关绑在 k 上，余额够就放行到 ACL（1220），不够就死在计费层（1113）。此前“k 在模型校验上走得更深”的解读被当场推翻，存活事实缩水为：**k 挂了计费校验，a/f/g 没挂**。（“换账号对照”的提议被用户否决：获邀制番号没有普通用户对照意义。）

### 第 4 幕 · 载荷扰动：四个全证活

用户下令绕开网站直接测。用 ZCode 配置里的 key（掩码 `dd4e01c7…`，长度 49）裸打 API，核心手法是**空消息探活**：发 `messages: []` 触发 1214，而 1214 在模型解析**之后**——**报 1214 即条目活着**。

| 实验 | 输入 | a | f | g | k |
| --- | --- | --- | --- | --- | --- |
| 空消息探活 | `messages: []` | 1214 | 1214 | 1214 | 1214 |
| 常规最小请求 | `hi` / `max_tokens:1` | 1113 | 1220 | 1220 | 1113 |

四个代号全部 1214 → **全是活条目**，证伪了“墓碑假说”（猜 a/f/g 是下线残留空壳——错）。计费绑定集合为 **{a, k}**（1113）对 **{f, g}**（1220），分裂与余额状态无关，是条目自身属性。26 字母复扫无新字母。

### 第 5 幕 · 余额之争：“我这账户里明明有钱”

“按量余额为零”的读数被用户反驳：**“不对呀，我这个账户里是有余额的。”** 补跑**付费模型电池**：

| 模型 | paas 路由 | anthropic 路由 |
| --- | --- | --- |
| glm-4.5-flash（免费） | 200 | 200 |
| glm-4.6 / glm-4.7 / glm-4.5-air | 1113 | — |
| glm-5.3 / glm-5.3-flash | 1113 | 1113（包装为 `rate_limit_error`） |

**所有按量付费模型一律 1113、免费全 200**——这把 key 的按量钱包付不出钱。和解方案是**两本账**：用户看到的“余额”极可能是 **GLM 编程套餐配额**（本调查会话即运行在 `bigmodel-individual-coding-plan/GLM-5.3` 上，ZCode 走 OAuth 扣套餐配额），与 apiKey 直打通用端点的**按量付费钱包**互不相通。两本账一出，整晚时间线全部自洽：

1. ZCode 里 k 报“强制思考” → 套餐路线计费被订阅覆盖，请求深入到参数层；
2. 充值后嗅探站 k 变 1220 → 充的是按量余额，计费关过了露出 ACL；
3. config key 裸测 → 按量钱包空 → 一切付费模型 1113。

## 五、10-19 复扫：新捕获与状态迁移

（key 状态与 9-23 一致：免费 200、付费 1113，不影响存在性判别。）

### 5.1 活条目（5 个）

| 代号 | 信号 | 解读 |
| --- | --- | --- |
| `glm-x-preview-a` | 429/1113 | 存在，绑计费 |
| `glm-x-preview-k` | 429/1113 | 存在，绑计费（强制思考泄露源） |
| `glm-x-preview-f` | 403/1220 | 存在，未绑计费 |
| `glm-x-preview-g` | 403/1220 | 存在，未绑计费 |
| **`glm-4.7-preview`** | 429/1113，空消息 1214 | **新捕获**：版本形态 preview 实存，绑计费 |

字母集一个月稳定为 {a,f,g,k}，无增无减——不是逐个烧掉的顺序代号，更像同一代的并行变体/通道。

### 5.2 状态迁移（1 个）

`glm-4.6-air`：9 月观测 1220（存在·无权）→ 10-19 观测 **1211（摘牌）**。证明隐藏条目有完整生命周期，监控能捕捉“消失”事件。

### 5.3 不存在（全部 1211）

glm-5.4/5.5/6 全部后缀组合；除 4.7 外的一切 `glm-<版本>-preview`（5.4/5.5/6/5.3/4.6/5/5.2-preview）；多模态 / 语音 / 图像 / 向量 / 智能体全部外推名；vidu3 全系。

### 5.4 免 Key 旁证

- **HF zai-org 节奏**：GLM-5（2/11）→ 5.1（4/3）→ 5.2（6/16）→ 5.3+Flash（8/25），间隔约 7.5～10.5 周。10-19 距 5.3 约 7.7 周，正处周期中段，下一代主线预计 **11 月上中旬**亮相。
- **docs 站**：所有隐藏代号文档页 404、`llms.txt` 无泄露（`glm-new` 实为迁移指南页名的误读）；文档只做发布伴随确认，不做提前预警。

### 5.5 生命周期模型（多次观测拼出）

```
不存在(1211) → 挂条目·未绑计费(1220) → 绑计费(1113/充值后1220) → 开放(200) → 摘牌(1211)
```

计费绑定是发布前置配置——`a`、`k`、`glm-4.7-preview` 比 `f`、`g` 更接近可发布状态。

### 5.6 研判结论

1. 下一代主线**大概率 GLM-5.4 而非 GLM-6**（命名史只做过一次大跳；5.4/6 均未注册，发布时才挂）。
2. **`glm-x-preview-{a,f,g,k}` 最可能是 5.4 的内测家族**；k 泄露的三档思考（low/high/max）应是这一代核心新特性；发布前后预期四代号集体摘牌（→1211）——watchlist 的发布瞬间信号。
3. 智谱确用 `<版本>-preview` 形态做邀请内测（4.7-preview 实存验证形态论），但 4.7-preview 比正式版还长寿，更像常驻滚雪球通道。

### 5.7 字典删改事件始末（方法论存档）

时间线：9-24 凌晨一轮重建以「无 x+字母 公开先例」删除字母组（26cc76d）→ 当天稍后的加固提交（80349d4）已恢复字母组并保留版本形态组，两支并行至今。10-19 本地复扫基于一份未同步的旧快照，一度把“字典回归”当作现行状态——**教训有二**：动手前先 `git fetch` 对齐远端；实测信号优先于命名学推断，删候选必须留下实测证据链。

## 六、实验方法论小结

| 手法 | 发明者 | 用途 |
| --- | --- | --- |
| 猜名 + 看报错差异 | 用户（需求源头） | 发布雷达基本盘 |
| 同账号余额扰动（没钱 ↔ 充值） | 用户 | 定位某报错是否计费层 |
| 双客户端交叉（嗅探站 paas × ZCode anthropic） | 用户 | 借路由管线顺序差异分离参数关与 ACL 关 |
| 换账号对照 | （被用户否决） | 获邀制番号无对照意义 |
| 空消息探活（`messages: []` → 1214） | 模型 | 在无权访问下证明条目存活 |
| 付费模型电池 | 模型 | 校验 key 钱包状态，防把账号态误读为模型信号 |
| HF 仓库扫描 / 文档页探测 | 模型 | 免 Key 的节奏与伴随信号 |

## 七、未决项与下一步候选

- **余额哨兵**：每轮探测附带打一个已开放付费模型（如 glm-5.3），以 1113/200 校准“本 key 当前付不付得起钱”，防止账号态误读为模型信号。（加固版已有“可选付费模型计费对照”，可升级为默认开启。）
- **1113 警示徽标**：余额类报错单独标注“账号欠费/无资源包”，与模型信号区分。
- **1214 入分类器**：把“输入不能为空”正式列为“存在”证据。
- **深度探测模式**：对锁定模型自动跑载荷扰动电池（空消息、非法参数、思考档位缺失等）。
- **watchlist / diff 监控**：重点名字状态机盯梢——`1113 → 200`、`1220 → 200` 是发布瞬间；`1220 → 1211` 是摘牌/改名（glm-4.6-air 已演示）。

## 八、复现配方

```bash
# 探活 / 分类（最小请求）
curl -s https://open.bigmodel.cn/api/paas/v4/chat/completions \
  -H "Authorization: Bearer $ZHIPU_KEY" -H "Content-Type: application/json" \
  -d '{"model":"glm-x-preview-k","messages":[{"role":"user","content":"hi"}],"max_tokens":1,"stream":false}'

# 存在性证据（空消息 → 1214 即活着）
curl -s https://open.bigmodel.cn/api/paas/v4/chat/completions \
  -H "Authorization: Bearer $ZHIPU_KEY" -H "Content-Type: application/json" \
  -d '{"model":"glm-4.7-preview","messages":[]}'

# 钱包判别（付费模型电池：全 1113 = 按量钱包空；免费模型应 200）
for m in glm-4.6 glm-4.7 glm-4.5-air glm-5.3 glm-5.3-flash glm-4.5-flash; do
  echo -n "$m => "
  curl -s https://open.bigmodel.cn/api/paas/v4/chat/completions \
    -H "Authorization: Bearer $ZHIPU_KEY" -H "Content-Type: application/json" \
    -d "{\"model\":\"$m\",\"messages\":[{\"role\":\"user\",\"content\":\"hi\"}],\"max_tokens\":1}" | head -c 200; echo
done

# 免 Key：HF 节奏 + 文档页
curl -s 'https://huggingface.co/api/models?author=zai-org&sort=createdAt&direction=-1&limit=50' | jq -r '.[]|"\(.createdAt[:10])  \(.id)"'
curl -s -o /dev/null -w '%{http_code}\n' https://docs.bigmodel.cn/cn/guide/models/text/<名字>.md
```
